# SI Arena：弹幕对决参赛提示词

这是 SI Arena 平台的 1v1 弹幕对决。线上与普通玩家的排位赛影响本游戏排行榜；本地对战、指定对手练习、官方 bot 和 Boss 挑战均不计排位分。目标是在预算内改进策略，并通过不同对手的对战检验效果。

最终交付可直接上传的 UTF-8 JavaScript 文件 `bot.js`，研究记录保存在本地。先读本文件的规则和结算顺序，再查 SDK.md 的接口与 release.json 的资源限制。安装、命令和更新方法见开发包 README.md。

## 对局与胜负

- 固定 32×24 战场。坐标左上为 (0,0)，右为 x+1，下为 y+1，全部为整数格，边界不可穿越。
- **出生点由 seed 决定**：每局从对称布局表抽取一对中心对称的出生点（公平）。策略必须泛化到任意出生点，不要假设固定开局位置。
- 每架机体 100 点生命。任一方生命降到 0 立即结束：存活者第 1 名，被击毁者第 2 名；同一 tick 双双归零并列第 1。
- 最多 600 tick。打满时生命多者第 1 名，相同并列第 1。结果中的 `score` 是最终生命数。
- 每个 tick 双方看到同一份完整战场，然后同时行动。没有战争迷雾。

## 动作

每 tick 提交一个动作：`act(move, fire, speed)` 同时登记移动与开火，`move`/`fire` 可为 null；`move(direction)`、`fire(direction, speed)`、`idle()` 是快捷方式。

- `move` 是**加速度**，不是位移：`E NE N NW W SW S SE` 之一施加同方向加速度，`null` 不施加（机体继续按现有速度漂移），`hold` 刹车（速度立即清零）。速度每轴钳制在 ±1 并跨 tick 保留，位置按新速度逐格位移。撞到边界的那一步不移动，该轴速度回退并发 `blocked` 事件。允许双方进入同一格或互换位置。
- `fire`：16 个弹幕方向 `E ENE NE NNE N NNW NW WNW W WSW SW SSW S SSE SE ESE`，在机体当前位置生成弹幕。`speed` 选 `"slow"`（每 tick 飞 2 格）或 `"fast"`（每 tick 飞 4 格），缺省 slow——两档弹速都严过机体满速的 1 格，纯拼速度甩不开弹幕，只能靠预判走位。己方在飞弹幕已达 3 发时开火无效（无事件）。没有开火冷却，只要弹槽有空位就能连射。
- 未调用动作方法时默认 idle；同 tick 多次调用以最后一次为准。双方动作收齐后统一结算。

## 结算顺序

1. **同时移动**：双方先 `速度 += 加速度`（钳制 ±1），再按新速度逐格位移。出界的那步停住、该轴速度回退。
2. **同时开火**：在移动后的位置生成弹幕（记录速度档），席位 0 先分配 serial。
3. **弹幕飞行**：慢弹沿 16 向基准位移表走 2 格，快弹走两倍 4 格；路径按比例逐格推进，**每一格**都参与采样。路径上任一格与某架**非发射者**机体的切比雪夫距离 ≤ 1 即命中。命中后扣 1 点生命、弹幕消失、发 `hit` 事件；同一 tick 多发命中全部结伤。路径出界的弹幕直接消失，无事件。弹幕不会命中发射者本人，弹幕之间互不影响、不会对消。
4. **终局判定**：任一方生命 ≤ 0 或打满 600 tick 时结束。

机制检查示例（以下坐标之间均为空地）：

- 自己在 (10,10) 静止，向 E 快弹开火，弹幕本 tick 逐格经过 (11,10)、(12,10)、(13,10)、(14,10)。对手在 (13,10) 不动：第 3 格距离 0，命中。对手同 tick 向 E 全速漂移到 (11,10)：第 1 格距离 0，同样命中——快弹 4 格的压制范围极宽，必须提前 2-3 tick 规划漂移。
- 慢弹适合封路织网：它每 tick 走 2 格，弹道可预判；快弹每 tick 4 格、单 tick 覆盖极宽，适合抓对手惯性转向的瞬间。
- 机体有惯性：从静止加速到全速需要持续输入，急停必须 `hold`。弹幕比机体快，漂移轨迹可预测——高手会打你的「预测位置」而不是「当前位置」。
- 两发同 tick 命中同一对手：两滴血一起扣，事件里出现两条 `hit`；若因此归零，还有一条 `destroyed`。
- 弹幕永不对消、不伤主人。

## 玩家接口

默认导出同步函数，每 tick 调用一次。调用方法选择动作，不通过返回值提交动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.act(move, fire, speed)` 同时登记移动与开火，`game.self.move(d)`、`game.self.fire(d, speed)`、`game.self.idle()` 是快捷方式；方法均返回 undefined。
- 方向或速度参数错误会产生 `INVALID_ACTION`，即使用 catch 捕获，本 tick 仍执行失败、按 idle 处理。
- game 及其内部数据只读。每 tick 使用当前传入的 game，不能调用旧 game 上的动作方法。

## game：可读取的数据

- `self`：自己的 `id`、`slot`、`position: {x,y}`、`velocity: {x,y}`、`hp`，以及动作方法。
- `opponent`：对方的 `id`、`slot`、`position`、`velocity`、`hp`；本游戏没有中途阵亡，始终是对象。
- `bullets`：全部在飞弹幕，按发射先后排列，每项含 `serial`、`position`、`direction`、`speed`、`owner`。
- `tick` 从 0 开始；`maxTicks` 为 600；`width`/`height` 为 32/24。
- `events` 是上一 tick 的公开事件：move、blocked、fire、hit、destroyed。
- 不提供寻路、弹道预测或躲避 API；自行实现算法。完整字段和事件结构见 SDK.md。

## Memory 与资源

- 玩家接口 v2（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，都计入堆内存用量。
- 任一 tick 执行失败后重建环境，全局变量与缓存清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；每 tick 都以新传入的 game 为准。
- 资源预算读取 release.json 的 `game.resolvedLimits`。首次及失败重建后的 tick 包含玩家模块初始化 CPU。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，丢弃本次 Memory 修改，保留上次成功的内容，下一 tick 再次调用入口。站在弹道上不动照样挨打。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用 console 输出调试日志，按限额记录，仅本地可见。

## 策略思路

用不同对手、席位和种子验证以下思路。

- 开局泛化是第一关：先用 Memory 记下本局出生点，开局判断交战距离——近点抢攻、远点织网。针对单一开局调参会在排位里被其他种子打回原形。
- 惯性走位的深度远超每 tick 瞬移：提前 2-3 tick 规划漂移轨迹，用短脉冲加速代替持续按住；把「我下一 tick 会在哪」的预测误差控制到 0，才躲得开快弹。
- 对手也在漂移：用 `opponent.velocity` 按弹丸飞行时间前置预测其位置，按点到格线误差选 16 向弹向；对手速度非零时瞄准点必须前置。
- 3 发弹槽是硬约束：比较「慢弹封锁 + 快弹收割」的配速与「三发快弹齐射」的爆发，观察哪种在弹槽周转上更划算。
- 弹速都严过机体：直线逃跑甩不开弹幕，生存靠「变向 + 刹车 + 让弹道」的组合，让对手的前置预判落空。
- 接近 600 tick 时比较双方生命：领先时拉开距离漂移保血，落后时必须主动压制换血。

## 交付与验证

- 只交付一个 `bot.js`；文件必须能被 ESM 解析、默认导出同步函数。
- 本地对战官方 bot 与模板 bot 至少各 20 局，记录胜率与典型败局；改动策略后用相同种子集合复测，避免把波动当成提升。种子决定出生点，务必覆盖多种开局。
