# SI Arena：俄罗斯方块参赛提示词

这是 SI Arena 的单人挑战：一局只有你和 10×20 场地。目标是在有限 tick 和执行预算内提高消行得分，并用独立种子验证策略。线上榜单按历史最高分排名；本地比较还要看平均分和低分局，不能只挑最好的一场。

交付可直接上传的 UTF-8 JavaScript 文件 bot.js，研究记录保存在本地。先读本文件的规则，再查 SDK.md 的接口和 release.json 的资源限制。安装与命令说明见开发包 README.md。

## 对局与胜负

- 场地固定 10×20，坐标原点在左上，向右 x 增大、向下 y 增大；最多 1500 tick。
- 按 7-bag 发牌：每 7 块内 I、O、T、S、Z、J、L 各出现一次，顺序由种子决定。新块出生在 `(3, 0)`，rotation 为 0。
- `game.next` 只提供下一块类型，不能读取内部随机数状态或完整后续队列。
- 每 tick 登记一个动作：左右移动、下移一格、顺/逆时针旋转，或硬降；不调用动作方法时为 idle。
- 等级为 `1 + floor(lines / 10)`；重力间隔为 `max(1, 12 - (level - 1))` tick。
- 消行得分等于消行数乘以锁定时的等级。软降和硬降本身均不计分，也没有四行额外倍率、连击或 T-spin 奖励。
- 新块放不下即 top-out；打满 1500 tick 也结束。最终 rank 固定为 1，score 才是本局成绩。

## 结算顺序

每 tick 从当前世界出发，后续阶段使用前一阶段的结果：

1. 执行动作。越界或重叠的移动/旋转无效，但不算接口错误。硬降到底并立即锁定。
2. 未在本 tick 硬降锁定时推进重力计数；达到间隔后下移，触底则锁定。成功软降会重置下落计数，再进入本 tick 的重力阶段。
3. 锁定时合并方块、消除满行、计算得分，再更新等级、抽取新块并检查 top-out。
4. tick 加一，检查终局。

水平踢墙依次尝试原位、左 1、右 1、左 2、右 2。不提供完整 SRS 踢墙、hold 或锁定延迟。策略需要核对本发行的形状与旋转方式，不能直接套用其他俄罗斯方块规则。

## 玩家接口

```js
export default function tick({ game, Memory }) {
  // 这里只演示一次硬降，不是完整策略。
  game.self.drop();
}
```

- `game.self.move("left" | "right" | "down")`、`rotate("cw" | "ccw")`、`drop()` 登记意图；同 tick 最后一次调用生效，方法返回 undefined。
- 入口必须同步返回 undefined。错误的方向/旋转字面量会锁定 `INVALID_ACTION`，catch 后调用合法动作也不能恢复本 tick 提交。
- `game.board.cells` 是长度 200 的已锁定棋盘，0 为空，1–7 对应 I/O/T/S/Z/J/L；当前方块不在棋盘数组中。
- `game.piece` 给出当前块的 type、rotation、x、y；形状可参考 bots/official.js 的本地形状表，不能在玩家运行时 import。
- `game.tick` 为已完成的结算次数，本次动作参与第 tick + 1 次结算。`events` 是上一轮事件，首 tick 为空；字段详见 SDK.md。
- game 只读。每 tick 读取当前输入，不能调用旧引用上的动作方法。

## Memory 与执行预算

全局变量和闭包可在成功 tick 间缓存，仍占用 isolate 堆。失败后环境重建，只有上次成功的 JSON Memory 恢复；当前动作和 Memory 修改一起丢弃，改用 idle，规则仍会推进重力。没有合法动作不等于游戏世界停止。

资源值读取 release.json 的 `game.resolvedLimits`。玩家模块初始化、入口、动作方法、日志与输出序列化计入 CPU；`stackBytes` 是保留字段，不控制 V8 线程栈。Memory 只保存 JSON 数据，不保存 Map、函数或 game。

玩家代码不能使用 import、require、网络、文件或 Node API；入口不返回 Promise，不依赖现实时间或 Math.random。console 日志仅在本地按预算捕获。

## 策略假设

以下是需要对照实验的思路，不是保证有效的规则：

- 比较聚合高度、空洞、列间起伏和即时消行的不同权重，分析低分局首先出现了什么问题。
- 比较只看当前块与利用 next 的浅层搜索，同时测量首次初始化和热 tick 的 CPU。
- 比较立即消行与暂时保留可填空隙。没有四行额外倍率，等待 I 块不一定比尽快消行好。
- 比较更早硬降与更多横移/旋转；硬降不直接加分，但可能节约 tick，让一局处理更多方块。必须验证目标落点在重力推进过程中确实可达。

## 本游戏验证方法

分别运行候选与官方示例，用相同种子比较；单人局不传 --opponent：

```sh
pnpm arena run --bot ./bot.js --matches 20 --seed 42
pnpm arena run --bot ./bots/official.js --matches 20 --seed 42
```

预算允许时使用 20 局或更多样本；不能完成时报告实际场数。优先排除执行错误，再比较平均分、逐种子分差和 top-out 情况。最终验证使用未参与调参的另一组种子，预算与停止条件遵守公共流程，不因未超过官方分数无限延长研究。

用 `pnpm arena dev --bot ./bot.js` 查看低分局。重点核对旋转踢墙、触底软降、硬降后是否再推进重力，以及跨等级消行采用哪个等级计分。没有工具时只能说明推演结果，不声称已通过对战验证。
