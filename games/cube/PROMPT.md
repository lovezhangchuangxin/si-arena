# SI Arena：魔方参赛提示词

这是 SI Arena 的单人挑战：一局只有一个打乱的三阶魔方。目标是用尽量少的步数还原它——每步扣 10 分，满分 2000，没还原不计分。线上榜单按历史最高分排名；本地比较要看平均步数与失败局，不能只挑最好的一场。

交付可直接上传的 UTF-8 JavaScript 文件 bot.js，研究记录保存在本地。先读本文件的规则，再查 SDK.md 的接口和 release.json 的资源限制。安装与命令说明见开发包 README.md。

## 对局与胜负

- 三阶魔方 54 个贴纸，六个面 U R F D L B，每面 9 个；贴纸的值就是它所属面的序号。
- 开局把 22 步随机转动作用在还原态上；同面不连续、同轴不三连。打乱序列不公开，只有步数公开。
- 最多 400 tick。每 tick 登记一个动作：转一个面，或者空过。
- 18 个转动名字：`U` `U2` `U'` `D` `D2` `D'` `L` `L2` `L'` `R` `R2` `R'` `F` `F2` `F'` `B` `B2` `B'`。
- 每走一步扣 10 分；200 步之后得分归零。空过不扣分，但消耗 tick。
- 还原即结束，得分 `max(0, 2000 - 10 × 步数)`；打满 400 tick 未还原记 0 分。最终 rank 固定为 1，score 才是本局成绩。

## 结算顺序

每 tick 从当前世界出发：

1. 若提交了转动且魔方未还原，执行转动，步数加一，产生 `turn` 事件。
2. 转动后若还原，置 `solved`、写入得分、产生 `solved` 事件，本局结束。
3. tick 加一；达到 400 tick 时以 `tick-limit` 结束。

转动永远合法，没有「撞墙」或「无效动作」。空过是合法的思考时间。

## 玩家接口

```js
export default function tick({ game, Memory }) {
  // 这里只演示一次转动，不是完整策略。
  game.self.turn("R");
}
```

- `game.self.turn(move)` 登记意图；同 tick 最后一次调用生效，方法返回 undefined。
- 入口必须同步返回 undefined。错误的转动名字会锁定 `INVALID_ACTION`，catch 后调用合法动作也不能恢复本 tick 提交。
- `game.facelets` 是长度 54 的贴纸数组；还原态是每个贴纸等于 `floor(下标 / 9)`。
- `game.moves` 是已走步数，`game.score` 未还原时恒为 0，`game.solved` 为真时本局立即结束。
- `game.tick` 为已完成的结算次数，本次动作参与第 tick + 1 次结算。`events` 是上一轮事件，首 tick 为空；字段详见 SDK.md。
- game 只读。每 tick 读取当前输入，不能调用旧引用上的动作方法。

## Memory 与执行预算

全局变量和闭包可在成功 tick 间缓存，仍占用 isolate 堆。失败后环境重建，只有上次成功的 JSON Memory 恢复；当前动作和 Memory 修改一起丢弃，改用空过，本 tick 白费但不改变魔方。把「待执行的算法」放进 Memory 是划算的：一 tick 只算一个算法，失败后还能接着走。

资源值读取 release.json 的 `game.resolvedLimits`。玩家模块初始化、入口、动作方法、日志与输出序列化计入 CPU；`stackBytes` 是保留字段，不控制 V8 线程栈。Memory 只保存 JSON 数据，不保存 Map、函数或 game。

玩家代码不能使用 import、require、网络、文件或 Node API；入口不返回 Promise，不依赖现实时间或 Math.random。

## 策略假设

以下是需要对照实验的思路，不是保证有效的规则：

- 分层法（底面十字 → 第一层角 → 中层棱 → 顶层四步）稳定但步数多，官方 bot 平均约 138 步；换更少的中间层算法或合并顶层步骤能显著压低步数。
- 两阶段搜索（先到子群，再在子群里求解）能把步数压到 25 步以内，代价是建表时间与堆占用；需要验证建表是否能在 tick 预算内摊开。
- 打乱只有 22 步，最优解通常不超过 20 步；但打乱序列不公开，逆向还原必须自己搜索。
- 每 tick 只算一个算法时，把中间状态写进 Memory 比每次从头推导更省 CPU；也要比较「多花几 tick 思考」与「多走几步」的得失——一步就是 10 分。
- 搜索深度与 CPU 预算的取舍要用真实 isolate 计时，不能只看本机 Node。

## 本游戏验证方法

分别运行候选与官方示例，用相同种子比较；单人局不传 --opponent：

```sh
pnpm arena run --bot ./bot.js --matches 20 --seed 42
pnpm arena run --bot ./bots/official.js --matches 20 --seed 42
```

预算允许时使用 20 局或更多样本；不能完成时报告实际场数。优先排除执行错误与未还原局，再比较平均步数、逐种子分差和最长局。最终验证使用未参与调参的另一组种子，预算与停止条件遵守公共流程，不因未超过官方步数无限延长研究。

用 `pnpm arena dev --bot ./bot.js` 查看失败局。重点核对：转动方向与贴纸编号是否和发行一致、还原判定是否按「每个贴纸回到自己的面」、失败 tick 之后 Memory 是否仍是上一份计划。没有工具时只能说明推演结果，不声称已通过对战验证。
