# SI Arena：网格圈地参赛提示词

这是 SI Arena 平台的 1v1 网格圈地竞技。线上与普通玩家的排位赛影响本游戏排行榜；本地对战、指定对手练习、官方 bot 和 Boss 挑战均不计排位分。目标是在预算内改进策略，并通过不同对手的对战检验效果。

最终交付可直接上传的 UTF-8 JavaScript 文件 `bot.js`，研究记录保存在本地。先读本文件的规则和结算顺序，再查 SDK.md 的接口与 release.json 的资源限制。安装、命令和更新方法见开发包 README.md。

## 对局与胜负

- 30×30 网格上的两人对抗。坐标左上为 (0,0)，右为 x+1，下为 y+1，边界不可穿越。
- 开局各有 3×3 领地，其中心格是你的出生点；两个出生点关于中线对称，种子决定你在哪一侧。
- 固定打满 500 tick，没有提前结束；双方永不淘汰，被重置也照常继续。
- 每个 tick 双方看到同一张完整地图，然后同时行动。
- 500 tick 打满后按最终领地格数排名，多者获胜，相同则并列第一。

## 核心循环：外出画尾迹，回城圈地

- 头部在领地外每移动一格，走过的格子就成为你的尾迹；在外原地停留不延长尾迹。当前位于领地外的头部格也在尾迹里。
- 带着尾迹走进任意一格自己的领地即闭合。尾迹不需要绕成环，两端接上己方领地即可。
- 闭合时，把现有领地和尾迹当作屏障，从地图边缘沿上、下、左、右搜索（洪泛填充）。搜索不到的格子归你，包括对手的领地；对手站在其中也不会被重置。双方同一 tick 闭合时，都圈住的中立格保持中立，圈住的对方领地仍可夺取。
- 闭合结算后尾迹清空。领地不要求连通，断开的格子照常保留，任何一格己方领地都可以作为回城点。
- 领地降为 0 不会出局：你仍能移动、仍能切断对手，但本局再也无法闭合圈地，只能阻断对手扩张。
- 尾迹完全暴露：对手的目标格（这一 tick 要去的格子，停留就是原地）落到你尾迹的任何一格上，你这次外出就被重置。每次扩张都在权衡圈多少面积与能否安全回城。

## 碰撞与重置

先用行动前的位置和尾迹检查以下情况，再统一处理重置。被重置的玩家清空尾迹、回到出生点，保留全部领地；本 tick 不执行原动作，也不圈地。

- 移动越界（不会自动转向）。
- 双方目标格相同，包括一方原地停留、被对方走进：双方都重置。
- 双方交换位置：双方都重置。
- 移动进入自己的尾迹（原地停在自己尾迹所在格不算）。
- 踩到对手的尾迹：尾迹的主人被重置，这叫“切断”。踩入者若同时撞头等，也会被重置。
- 本 tick 新画出的尾迹还安全，从下一 tick 起才能被切断。
- 被重置的一方落点（出生点）若与对手本 tick 的落点重合：双方都重置。

若出生点领地已被对手圈走，重置会在出生点留下一格尾迹，下一 tick 可能再次被切断。

例如：即使本 tick 已选择回城，对手在同次结算中踩到旧尾迹仍会先重置你，闭合不会生效。

## 玩家接口

默认导出同步函数，每 tick（一次游戏更新）调用一次。调用方法选择动作，不通过返回值提交动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 移动一格，`game.self.idle()` 停留；方法均返回 undefined。
- 未调用动作方法时默认停留；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，双方动作收齐后统一结算。
- 入口只能返回 `undefined`。返回对象或 Promise 会产生 `ENTRYPOINT_ERROR`；方向等动作参数错误会产生 `INVALID_ACTION`。即使用 catch 捕获错误，本 tick 仍执行失败。
- game 及其内部数据只读。每 tick 使用当前传入的 game，不能调用旧 game 上的动作方法。

## game：可读取的数据

- `self` 与 `opponent`：各自的 id、slot、position（当前头部坐标）、spawn（出生点）；只有 self 有动作方法。
- `board.width`、`board.height` 为 30、30；`board.territory` 与 `board.trails` 是长度 900 的数组，下标 `y * width + x`，-1 为无主/无尾迹，0、1 为所属席位。
- `tick` 从 0 开始，表示已完成的结算次数；`maxTicks` 为 500。
- `events` 是上一 tick 结算产生的公开事件，首个 tick 为空。包括 move、capture、trail-cut、reset；reset 的 playerId 是被重置者，causes 包含重置原因。用它清除失效的计划，不必靠猜位置推断对手被重置。
- 双方永不淘汰，位置始终有效；没有 alive 字段，也读不到随机数内部状态。
- 不提供寻路、安全方向、威胁判断或扩张策略 API；自行实现算法。完整字段和事件结构见 SDK.md。

## Memory 与资源

- 玩家接口 v2（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，都计入堆内存用量。
- 任一 tick 执行失败后重建环境，全局变量、缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；每 tick 都以新传入的 game 为准。
- 资源预算读取 release.json 的 `game.resolvedLimits`，不要把其他游戏或旧发行的数值当作当前上限。首次及失败重建后的 tick 包含玩家模块初始化 CPU；`stackBytes` 是协议保留字段，不代表按该字节数限制 V8 线程栈。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，丢弃本次 Memory 修改，保留上次成功的内容，下一 tick 再次调用入口。持续出错不会出局，只会一直浪费回合。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用 console 输出调试日志，按限额记录，仅本地可见。

## 策略思路

以下思路需要实测。比较最终面积和对不同对手的表现，不只看单次圈占面积。

- 比较短回环与长回环最终增加了多少领地，同时记录外出时间、重置频率和被夺走的领地；回城时间应与对手到整条尾迹的距离比较，同次结算被切断也算失败。
- 比较自己扩张和追击对手的效果。重置不会清空已有领地，持续追击可能阻止扩张，也可能浪费自己的增长时间。
- 领地可以不连通，任何己方格子都能闭合；每 tick 重新检查回城点是否仍归自己，不长期使用旧地图规划。
- 接近 500 tick 时比较守住领先与争夺面积的效果。没有提前结束，不能因一次大圈占或暂时领先就停止行动。

## 验证方法

- 对战命令：`pnpm arena run --bot ./bot.js --matches 20 --seed 42`（种子 42–61）。对战本地历史版本可用 `pnpm arena run --bot ./bot.js --opponent ./research/best-v1.js --matches 20 --seed 42`；先保存该历史文件。记录胜平负和执行错误；达到某个胜率后仍应继续有价值的实验。
- 分析败局：events 里的 reset、trail-cut 记录了每次重置的原因与责任方，据此定位是圈地贪心、安全余量不足还是进攻时机错误。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：在浏览器打开命令输出的网址，整场结束后逐 tick 查看双方行为。
