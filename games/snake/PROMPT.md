# SI Arena：贪吃蛇大作战参赛提示词

这是 SI Arena 平台的贪吃蛇竞技：最多 4 条蛇同场，死亡即出局，线上竞技场按最终名次结算贪吃蛇排位分（初始 1000）。目标是在预算内改进策略，并通过不同对手的对战检验效果。

最终交付可直接上传的 UTF-8 JavaScript 文件 `bot.js`，研究记录保存在本地。先读本文件的规则和结算顺序，再查 SDK.md 的接口与 release.json 的资源限制。安装、命令和更新方法见开发包 README.md。

## 对局与名次

- 2–4 条蛇同场。正方形地图，边长 `11 + 2 × 人数`：2 人 15、3 人 17、4 人 19。坐标左上为 (0,0)，右为 x+1，下为 y+1，边界不可穿越。
- 开局每条蛇 3 节重叠在出生格上，体力 100。出生点为四个角各向内缩 2 格，种子决定谁站在哪个角；左半边的蛇朝右，右半边的蛇朝左。
- 初始食物在地图正中央，以及每条蛇出生点沿 x、y 各向中心移 2 格处各一个。
- 每个 tick 所有存活玩家看到同一张完整地图，然后同时行动。最多 500 tick。
- **死亡即出局**：身体立即移出地图，不再收到观察，也不再执行代码。
- 存活不超过 1 条时立即结束，存活者第 1 名。到 500 tick 时存活者按长度排名，相同并列。
- 出局者排在所有存活者之后，出局越晚名次越好；同一 tick 出局的并列。所有蛇同一 tick 同归于尽时全部并列第 1。
- 线上排位按 Elo 逐对结算：普通参赛者之间按名次定胜/平/负，并列记平局；分数变化还取决于双方赛前排位，不能直接用名次推断涨分多少。官方 bot 不参与计分；本地比赛不改变线上排位。活下来比长得长更重要。

## 核心循环：吃食物、省体力、留空间

- 体力每 tick 减 1，吃到食物恢复到 100 并长一节（这一 tick 不去尾）。体力减到 0 的那个 tick 没有吃到食物就饿死，所以每 100 tick 内至少要吃一次。
- 地图上的食物少于存活蛇数（至少 1）时，每 tick 结算末尾随机补一个，另有 15% 几率再补一个。食物只会出现在空格上。
- 蛇不能停留，每 tick 必须前进一格；反向移动会撞进自己的脖子。
- 头对头比较本 tick 进食后的长度：更短的一方死，相同长度同归于尽；其他撞身原因仍独立判定，较长不代表免疫碰撞。

## 出局判定

所有蛇根据行动前的同一个局面选择动作，再按顺序结算。碰撞使用移动和进食后的身体；同一条蛇可能同时满足多个出局原因：

1. 体力：每条存活的蛇体力减 1。
2. 移动：每条蛇在目标格新增头部；目标格上有食物则吃掉它（体力回满、不去尾），否则去掉尾节。多条蛇同时进入同一食物格时都算吃到，再按相撞处理。
3. 死亡判定（对移动后的身体同时判定）：
   - 越界（`boundary`）：目标格在地图外。
   - 饿死（`starvation`）：体力减到 0 且本 tick 没有吃到食物。
   - 撞身（`body-collision`）：头部与任意一条蛇（包括自己）移动后除头部外的任意一节重合。尾节本步移走的格子可以进入；对方本 tick 吃到食物时尾巴不动，进入它就撞上。开局重叠的三节没有展开前，尾巴所在格始终被占用。
   - 头对头（`head-collision`）：头部与另一条蛇的头部同格，长度（含本 tick 的增长）较短者死，相同则都死。
4. 清理：本 tick 死亡的蛇身体全部移出地图。
5. 食物生成：按上一节规则补充食物。
6. tick 加 1；存活不超过 1 条或到 500 tick 时结束。

## 玩家接口

默认导出同步函数，每 tick（一次游戏更新）调用一次。调用方法选择动作，不通过返回值提交动作：

```js
export default function tick({ game, Memory }) {
  game.self.move(game.self.heading);
}
```

- `game.self.move("up" | "right" | "down" | "left")` 登记移动一格；方法返回 undefined。
- 不调用时默认沿当前 `heading` 前进；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，所有动作收齐后统一结算。
- 入口只能返回 `undefined`。返回对象或 Promise 会产生 `ENTRYPOINT_ERROR`；方向等动作参数错误会产生 `INVALID_ACTION`。即使用 catch 捕获错误，本 tick 仍执行失败。
- game 及其内部数据只读。每 tick 使用当前传入的 game，不能调用旧 game 上的动作方法。

## game：可读取的数据

- `self`：自己的 `id`、`slot`、`body`（从头到尾的格子数组）、`head`（等于 `body[0]`）、`length`、`health`、`heading`，以及 `move` 方法。
- `opponents`：其他存活的蛇，按 slot 排列，字段同 self 但没有动作方法。
- `eliminated`：已出局玩家的 `id`、`slot`、`tick`（出局时已完成的 tick 数）与 `causes`。
- `board.width`、`board.height` 为地图边长；没有网格数组，身体与食物都是格子列表。
- `food`：地图上的食物格子，按 `y * width + x` 升序。
- `tick` 从 0 开始，表示已完成的结算次数；`maxTicks` 为 500。
- `events` 是上一 tick 结算产生的公开事件，首个 tick 为空：move、eat、death、food-spawn。death 的 causes 给出出局原因。
- 不提供寻路、安全方向或觅食 API；自行实现算法。完整字段和事件结构见 SDK.md。

## Memory 与资源

- 玩家接口 v1（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，都计入堆内存用量。
- 任一 tick 执行失败后重建环境，全局变量、缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；每 tick 都以新传入的 game 为准。
- 资源预算读取 release.json 的 `game.resolvedLimits`，不要把其他游戏或旧发行的数值当作当前上限。首次及失败重建后的 tick 包含玩家模块初始化 CPU；`stackBytes` 是协议保留字段，不代表按该字节数限制 V8 线程栈。
- 抛错、超时、非法动作或超限时：该 tick 按沿当前 heading 前进处理，丢弃本次 Memory 修改，保留上次成功的内容，下一 tick 再次调用入口。默认前进不会避险：前方是墙或蛇身时照样出局。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用 console 输出调试日志，按限额记录，仅本地可见。

## 策略思路

以下思路需要实测。区分确定会发生的碰撞和对手可能带来的风险。

- 先排除越界与确定撞身的动作。重建移动后的身体：旧头会成为颈部，未进食时尾节移走，进食时尾节保留；不能只在当前身体图上寻路。对手下一步可能到达的格子需要防备，但并非都会被占用。
- 头对头比较的是本 tick 进食后的长度；即使自己更长，也仍可能同时撞到身体。用抢食、交换头部位置和进入刚移走的尾格等局面检查预测。
- 洪泛可估计当前可达空间，但蛇身会移动，静态空间小于长度并不必然是死胡同。比较静态空间启发式与考虑尾部释放时间的规划，检查是否因过度保守放弃可行路线。
- 在低体力时提高觅食优先级，同时比较食物距离、对手可能增长与替代食物。双方争同一食物可能发生头对头，反复避让也可能饿死，不能只用“距离相同就放弃”决定。
- 尝试用身体限制更短对手的活动空间，但同时保留自己的进食路线与出口；分别用进攻型和保守型对手验证。

## 验证方法

- 满员对战命令：`pnpm arena run --bot ./bot.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --matches 20 --seed 42`。逐场读取 `match` 行的 `result.players`，按玩家 ID 统计冠军率和平均名次，并检查执行错误；批量胜负汇总不足以描述多人表现。用本地历史文件替换部分 --opponent，组成混合阵容。
- 只给 `--bot` 时自动加入 3 个官方对手，组成 4 人局；给出 `--opponent` 后人数等于 1 + 对手数，最多 3 个对手。两人局（一个 `--opponent ./bots/official.js`）与四人局都要测：地图大小随人数变化。
- 分析败局：events 里的 death 记录了每次出局的原因，据此定位是饿死、追食物撞身、被堵死还是头对头吃亏。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：在浏览器打开命令输出的网址，整场结束后逐 tick 查看各方行为。
