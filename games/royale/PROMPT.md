# SI Arena：圈地大逃杀参赛提示词

这是 SI Arena 平台的大逃杀竞技：最多 5 个 bot 同场，被淘汰即出局，线上竞技场按最终名次结算大逃杀排位分（初始 1000）。目标是在预算内改进策略，并通过不同对手的对战检验效果。

最终交付可直接上传的 UTF-8 JavaScript 文件 `bot.js`，研究记录保存在本地。先读本文件的规则和结算顺序，再查 SDK.md 的接口与 release.json 的资源限制。安装、命令和更新方法见开发包 README.md。

## 对局与名次

- 2–5 人同场。正方形地图，边长 `max(20, ceil(sqrt(320 × 人数)))`：2 人 26、3 人 31、4 人 36、5 人 40。坐标左上为 (0,0)，右为 x+1，下为 y+1，边界不可穿越。
- 开局各有 3×3 领地，中心格是出生点；出生点等角分布在以地图中心为圆心、半径约 0.32 × 边长的圆上，种子决定起始角和谁站在哪里。
- 每个 tick 所有存活玩家看到同一张完整地图，然后同时行动。最多 800 tick。
- **被淘汰即出局**：领地和尾迹全部变回无主地，不再收到观察，也不再执行代码。
- 存活人数不超过 1 时立即结束，存活者第 1 名。到 800 tick 时存活者按领地格数排名，相同并列。
- 出局者排在所有存活者之后，出局越晚名次越好；同一 tick 出局的并列。所有人同一 tick 出局时全部并列第 1。
- 线上排位按 Elo 逐对结算：普通参赛者之间按名次定胜/平/负，并列记平局；分数变化还取决于双方赛前排位，不能直接用名次推断涨分多少。官方 bot 不参与计分；本地比赛不改变线上排位。活下来比圈得多更重要。

## 核心循环：外出画尾迹，回城圈地

- 头部在自己领地外每移动一格，走过的格子就成为你的尾迹；在外原地停留不延长尾迹。当前位于领地外的头部格也在尾迹里。
- 带着尾迹走进任意一格自己的领地即闭合。尾迹不需要绕成环，两端接上己方领地即可。
- 闭合时，把现有领地和尾迹当作屏障，从地图边缘沿上、下、左、右搜索（洪泛填充）。搜索不到、且原本不属于你的格子，就是本次“圈占”的范围。只被你一人圈占的格子归你，包括别人的领地；同一 tick 被多人圈占的格子保持原状。
- 圈占的格子上若有别人的尾迹，尾迹的主人出局，即使这个格子因多人争夺没有易手。尾迹压在你原有领地上的人不受影响。
- 闭合后尾迹清空。领地不要求连通，断开的格子照常保留，任何一格己方领地都可以作为回城点。
- 别人圈走你脚下的领地不会让你出局，但你立刻站在领地外，脚下这一格成为你的尾迹，随时可能被切断。
- 领地降为 0 不会出局，但再也无法闭合；只能躲避、切断别人，或等别人先出局。

## 出局判定

所有玩家根据行动前的同一个局面选择动作。先用旧位置、旧尾迹判定撞头与切断，再移动、圈地和处理安全区；同一玩家可能同时满足多个出局原因：

1. 越界（`boundary`）：移动出地图。
2. 撞头：两个及以上头部的目标格相同，全部出局（`head-collision`），包括一方原地停留、被别人走进；两人互换位置，双方出局（`head-swap`）。
3. 切尾迹：踩到其他玩家的尾迹，尾迹的主人出局（`trail-cut`）；踩入者即使同 tick 撞头出局，切断仍生效。移动进入自己的尾迹也会出局（`self-trail`）；原地停在当前头部格不算。
4. 其余玩家移动、留下尾迹。本 tick 新画出的尾迹从下一 tick 起才能被切断。
5. 圈地：见上一节，圈占格上的他人尾迹主人出局（`enclosed`）。
6. 安全区：若本 tick 是缩圈 tick，先缩一圈；之后头部位于安全区外的玩家出局（`zone`）。
7. 本 tick 出局的玩家领地与尾迹全部清空，头部移出地图。

## 安全区

- 安全区是居中的正方形，开局等于整张地图。目标边长为 `max(10, ceil(sqrt(320 × 存活人数)))`。
- 当前边长大于目标时，在第 10、20、30…次结算中向内收缩一圈（边长减 2），直到不大于目标。是否收缩按该 tick 开始时的存活人数判断；本 tick 新出局的人数从下一 tick 起影响缩圈。
- 收缩时，落到安全区外的领地和尾迹立即变回无主地；头部留在安全区外的玩家在同一 tick 出局。安全区外的格子永远是无主地，走出去当场出局。
- `game.zone.ticksToNextShrink` 告诉你还要几个 tick 发生下一次收缩（1 表示下一次结算就收缩），不收缩时为 `null`。有人出局后最少只有 1 个 tick 的预警，贴边扩张要留余量。

## 玩家接口

默认导出同步函数，每 tick（一次游戏更新）调用一次。调用方法选择动作，不通过返回值提交动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 移动一格，`game.self.idle()` 停留；方法均返回 undefined。
- 未调用动作方法时默认停留；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，所有动作收齐后统一结算。
- 入口只能返回 `undefined`。返回对象或 Promise 会产生 `ENTRYPOINT_ERROR`；方向等动作参数错误会产生 `INVALID_ACTION`。即使用 catch 捕获错误，本 tick 仍执行失败。
- game 及其内部数据只读。每 tick 使用当前传入的 game，不能调用旧 game 上的动作方法。

## game：可读取的数据

- `self`：自己的 `id`、`slot`、`position`（当前头部坐标）、`spawn`（出生点）、`area`（领地格数），以及两个动作方法。
- `opponents`：其他存活玩家，按 slot 排列，字段同 self 但没有动作方法。
- `eliminated`：已出局玩家的 `id`、`slot`、`tick`（出局时已完成的 tick 数）与 `causes`。
- `board.width`、`board.height` 为地图边长；`board.territory` 与 `board.trails` 是长度 width×height 的数组，下标 `y * width + x`，-1 为无主/无尾迹，0–4 为所属席位。
- `zone`：`size` 当前边长，`target` 目标边长，`min` 左上角格子 `{x, y}`（右下角为 `min + size - 1`），`ticksToNextShrink`。
- `tick` 从 0 开始，表示已完成的结算次数；`maxTicks` 为 800。
- `events` 是上一 tick 结算产生的公开事件，首个 tick 为空：move、trail-cut、capture、zone-shrink、death。death 的 causes 给出出局原因。
- 不提供寻路、安全方向、威胁判断或扩张策略 API；自行实现算法。完整字段和事件结构见 SDK.md。

## Memory 与资源

- 玩家接口 v1（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，都计入堆内存用量。
- 任一 tick 执行失败后重建环境，全局变量、缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；每 tick 都以新传入的 game 为准。
- 资源预算读取 release.json 的 `game.resolvedLimits`，不要把其他游戏或旧发行的数值当作当前上限。首次及失败重建后的 tick 包含玩家模块初始化 CPU；`stackBytes` 是协议保留字段，不代表按该字节数限制 V8 线程栈。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，丢弃本次 Memory 修改，保留上次成功的内容，下一 tick 再次调用入口。停留不会自动避险：站在别人能走到的格子或即将消失的外圈上，停留同样可能出局。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用 console 输出调试日志，按限额记录，仅本地可见。

## 策略思路

以下思路需要实测。距离和预计面积只能辅助判断，不能保证安全。

- 比较每个对手到己方尾迹的最短距离与预计回城时间，初步判断是否有被切断的风险。切断在闭合前结算，同一次结算中对手踩到旧尾迹仍会淘汰你；另需检查撞头、自撞、被圈住和缩圈。
- 比较小而快的回环与更大面积的扩张，在不同人数和对手池中测量存活率与最终名次。最短回城路线也可能经过对手能抢占的格子，不能直接视为安全路线。
- 尝试在对手闭合前切断它，同时预测自己的尾迹风险、对手可选的回城点及其他玩家的行动。
- 检查他人可能闭合后圈占的区域，避免尾迹被圈住；仅跟踪对手头部距离会漏掉这类威胁。
- 临近缩圈时检查下一安全区与整条计划路线。有人出局会改变目标边长，应每 tick 重算，不长期沿用缓存中的缩圈计划。

## 验证方法

- 满员对战命令：`pnpm arena run --bot ./bot.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --matches 20 --seed 42`。逐场读取 `match` 行的 `result.players`，按玩家 ID 统计冠军率和平均名次，并检查执行错误；批量胜负汇总不足以描述多人表现。用本地历史文件替换部分 --opponent，组成混合阵容。
- 只给 `--bot` 时自动加入 4 个官方对手，组成 5 人局；显式给出 `--opponent` 后人数为 1 + 对手数，最多 4 个对手。两人局、五人局都要测：地图大小随人数变化。
- 分析败局：events 里的 death 记录了每次出局的原因，trail-cut 记录了切断者，据此定位是外出太贪、安全余量不足、被安全区吞掉还是进攻时机错误。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：在浏览器打开命令输出的网址，整场结束后逐 tick 查看各方行为。
