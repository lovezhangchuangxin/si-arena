# SI Arena：坦克对决参赛提示词

这是 SI Arena 平台的 1v1 坦克对决。线上与普通玩家的排位赛影响本游戏排行榜；本地对战、指定对手练习、官方 bot 和 Boss 挑战均不计排位分。目标是在预算内改进策略，并通过不同对手的对战检验效果。

最终交付可直接上传的 UTF-8 JavaScript 文件 `bot.js`，研究记录保存在本地。先读本文件的规则和结算顺序，再查 SDK.md 的接口与 release.json 的资源限制。安装、命令和更新方法见开发包 README.md。

## 对局与胜负

- 固定 21×15 地图上的两人对抗。坐标左上为 (0,0)，右为 x+1，下为 y+1，下标 `y * 21 + x`，边界不可穿越。
- 地形：0 空地、1 砖墙（被炮弹击中后变空地，炮弹同时消失）、2 钢墙（不可摧毁，挡住炮弹和坦克）。地图随种子生成，关于中心格 (10,7) 点对称；两个出生点周围 3×3 开局为空地，且两出生点之间一定存在不经过钢墙的通路，但可能需要先炸开砖墙。
- 席位 0 出生在 (1,7) 面朝右，席位 1 出生在 (19,7) 面朝左；种子不交换席位。
- 每辆坦克 3 点生命。任一方生命降到 0 立即结束：存活者第 1 名，被击毁者第 2 名；同一 tick 双双击毁并列第 1。
- 最多 600 tick。打满时生命多者第 1 名，相同并列第 1。结果中的 `score` 是最终生命值。
- 每个 tick 双方看到同一张完整地图，然后同时行动。

## 动作

- `move(direction)`：先把炮口转向 `up`、`right`、`down`、`left`，再尝试向该方向前进一格。目标格在地图外、是砖墙、钢墙，或是对方当前所在格且对方本 tick 没有移开时，只转向不移动。
- `fire()`：沿当前朝向开火。同一辆坦克同时只能有一枚炮弹在飞，已有炮弹时本 tick 的 fire 无效、也不会转向。
- `idle()`：停留。默认动作是 idle。
- **转向必须通过 move 完成**：想朝某个方向开火，就先 move 过去（撞墙或撞到对方时只转不走），下一 tick 再 fire。

## 同时结算

双方根据 tick 开始时的同一个局面选择动作，收齐后依次结算。后续步骤使用前面步骤更新的位置和地图：

1. **转向与移动**：登记 move 的坦克先改朝向。双方目标为同一格时都不移动；双方互换位置时都不移动；一方移入对方本 tick 离开的格子时允许移动。
2. **开火**：登记 fire 且没有在飞炮弹的坦克，在自己所在格生成一枚朝向等于自己朝向的炮弹。炮弹永远不会击中自己的坦克。
3. **炮弹飞行**：炮弹每 tick 前进 2 格，分两个子步。每个子步所有炮弹同时前进一格，然后判定：
   - 两枚炮弹进入同一格，或在本子步互换了格子：两枚都消失，不再产生其他效果（压在砖墙上对消时砖墙保留）。
   - 飞出地图或进入钢墙：消失。
   - 进入砖墙：砖墙变空地，炮弹消失。
   - 进入对方坦克所在格：对方生命减 1，炮弹消失。生命已经为 0 的坦克在本 tick 清理前仍占格、仍会吸收炮弹，但生命不再减少。
4. **清理**：生命为 0 的坦克被击毁，移出地图，其在飞的炮弹立即消失。
5. tick 加 1；任一方被击毁或达到 600 tick 时结束。

机制检查示例（以下坐标之间均为空地，除非另有说明）：

- 自己在 (5,7) 朝右开火，对手原在 (7,7)：若对手本 tick 移到 (7,6)，炮弹经过 (6,7)、(7,7)，不会命中。若对手停留，且没有其他炮弹对消，则在第二子步命中。距离近不代表必然命中，必须预测对手同 tick 的移动。
- 自己在 (5,7) 朝右开火，(6,7)、(7,7) 各有一块砖墙：只摧毁 (6,7)，炮弹消失，(7,7) 保留；后续需要再次开火。
- 双方在无遮挡的同一直线上相向开火，且都能成功发射时，两枚炮弹会在同格或交换格子时对消。墙体、已有炮弹和各自朝向会改变这个前提，不能把所有面对面局面都视为平局。
- 开始结算时已有自己的炮弹，本 tick 的 fire 无效；即使旧炮弹稍后撞墙消失，也不会补发。下一 tick 若已无自己的炮弹，就可再次开火，没有固定的多 tick 冷却。

## 玩家接口

默认导出同步函数，每 tick（一次游戏更新）调用一次。调用方法选择动作，不通过返回值提交动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 转向并前进一格，`game.self.fire()` 开火，`game.self.idle()` 停留；方法均返回 undefined。
- 未调用动作方法时默认停留；同 tick 多次调用以最后一次为准。位置、朝向和地图本 tick 不变，双方动作收齐后统一结算。
- 入口只能返回 `undefined`。返回对象或 Promise 会产生 `ENTRYPOINT_ERROR`；方向等动作参数错误会产生 `INVALID_ACTION`。即使用 catch 捕获错误，本 tick 仍执行失败。
- game 及其内部数据只读。每 tick 使用当前传入的 game，不能调用旧 game 上的动作方法。

## game：可读取的数据

- `self`：自己的 `id`、`slot`、`position`、`facing`、`hp`、`bulletInFlight`（为 true 时 fire 无效），以及三个动作方法。
- `opponent`：对方的同名公开字段，没有动作方法；对方存活时为对象，否则为 `null`（本游戏任一方被击毁即结束，所以存活期间总是对象）。
- `bullets`：所有在飞炮弹，每项含 `position`、`direction`、`ownerSlot`，按发射先后排列。
- `board.width`、`board.height` 为 21、15；`board.cells` 是长度 315 的地形数组，下标 `y * width + x`，值为 0、1、2。
- `tick` 从 0 开始，表示已完成的结算次数；`maxTicks` 为 600。
- `eliminated` 恒为空数组（一方被击毁时比赛结束，不再产生观察）。
- `events` 是上一 tick 结算产生的公开事件，首个 tick 为空：move、fire、hit、brick-destroyed、bullets-cancelled、death。
- 不提供寻路、射线、威胁判断或躲避 API；自行实现算法。完整字段和事件结构见 SDK.md。

## Memory 与资源

- 玩家接口 v1（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，都计入堆内存用量。
- 任一 tick 执行失败后重建环境，全局变量、缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；每 tick 都以新传入的 game 为准。
- 资源预算读取 release.json 的 `game.resolvedLimits`，不要把其他游戏或旧发行的数值当作当前上限。首次及失败重建后的 tick 包含玩家模块初始化 CPU；`stackBytes` 是协议保留字段，不代表按该字节数限制 V8 线程栈。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，丢弃本次 Memory 修改，保留上次成功的内容，下一 tick 再次调用入口。停留不会自动躲弹：站在对方射线上不动照样挨打。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用 console 输出调试日志，按限额记录，仅本地可见。

## 策略思路

用不同对手、席位和地图验证以下思路。

- 对每个候选动作先预测移动，再推进炮弹的两个子步；检查墙体、坦克阻挡和对消。横向躲避只有在能成功移动、且落点没有其他威胁时才安全，还要考虑对手本 tick 新发射的炮弹。
- 射击价值取决于对手可能的落点、逃生方向和炮弹是否会被砖墙或对方炮弹消耗。比较近距离施压、封锁出口与绕侧攻击，而非只判断当前是否同行同列。
- 把砖墙作为需要开火、等待炮弹消失后才能通过的通路，与绕路所需时间比较；路径代价随射距和对手威胁变化，不固定为某个步数。
- 用 Memory 记录最近的位置与目标，检查互相阻挡或绕柱追逐；换路是否改善结果应通过相同种子的对照比赛验证。
- 接近 600 tick 时比较双方生命与剩余进攻机会，验证领先保守和落后追击的效果。相同生命的结果是平局；线上 Elo 收益取决于双方排位，不能认为平局总是零收益。

## 验证方法

- 对战命令：`pnpm arena run --bot ./bot.js --matches 20 --seed 42`（种子 42–61）。对战本地历史版本可用 `pnpm arena run --bot ./bot.js --opponent ./research/best-v1.js --matches 20 --seed 42`；先保存该历史文件。记录胜平负和执行错误；达到某个胜率后仍应继续有价值的实验。
- 分析败局：events 里的 hit 记录了每次被命中的位置与攻击者，bullets-cancelled 记录了对消，据此定位是躲避太慢、逼近路线暴露在对方炮口下，还是对峙时白白浪费炮弹。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：在浏览器打开命令输出的网址，整场结束后逐 tick 查看双方行为。
