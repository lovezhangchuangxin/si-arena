# tick 执行与回放

## 三种运行方式，共用一套规则

| 方式       | 玩家代码                 | 规则 step | 输入来源               |
| ---------- | ------------------------ | --------- | ---------------------- |
| 服务端比赛 | 每 tick 沙箱执行         | 执行      | 玩家最新代码与世界观察 |
| 本地比赛   | 同一沙箱执行，可捕获日志 | 执行      | 本地代码与世界观察     |
| 回放       | 完全不执行               | 执行      | 初始世界与已记录动作   |

回放与任何历史 bot 源码、Memory、CPU 计时无关。代码替换或删除不影响已经保存的比赛回放。

## tick 的定义

定义 `S0` 为尚未执行任何动作的初始世界。记录 `tick: 0` 中的动作，将 `S0` 推进为 `S1`。依此类推，第 N 条动作记录产生 `SN`。

播放器显示“已完成 0 tick”时展示 `S0`。错误、日志关联其发生的输入 tick，而非动画帧。统一这一约定，避免界面、回放和 SDK 差一回合。

## 正式执行步骤

1. 从 `St` 为所有可行动玩家生成观察，同时传入上一 tick 的冻结事件供游戏筛选；tick 0 事件为空，不修改权威状态。
2. 将观察与各自上次成功提交的 Memory 发送给独立执行器。
3. 每位玩家在独立常驻 Runtime 中执行一次，首次或上一 tick 失败时创建新环境并重新初始化模块，通过该游戏的基础方法登记意图，包装器在入口正常结束后返回规范动作和候选 Memory。
4. 检查执行状态、动作协议和 Memory；失败则整体丢弃候选输出与易失环境，生成该游戏默认动作。
5. 固定本 tick 的规范动作集合、错误与可选本地日志，保存在有界的当前 tick 记录中。
6. 调用一次 `step(St, actions)`，得到 `St+1`、可视化事件和可选最终结果。
7. 规则推进与契约检查成功后追加该 tick 记录。成功玩家保留已验证并提交的 Memory，失败玩家保留旧 Memory。若游戏结束则保存回放并结算，否则进入下一 tick。

执行适配器在返回成功前校验规范动作并原子提交候选 Memory；规则随后出错时整场终止，不再使用该场 Memory，也不能计分。规则出错的当前 tick 不进入完整回放。通用引擎的接口、流式保存和本地示例见 [引擎说明](../../packages/engine/README.md)。

动作是**经过协议验证和归一化的意图**，不是移动后的结果。例如“向右移动”即使撞墙，仍是有效动作，由该游戏规则判定后果（如圈地中的重置）；方向字符串拼写错误才是非法动作。

同 tick 内只有一次世界结算。执行器返回次序不能改变动作集合或规则结果。已淘汰玩家不再执行代码，动作缺失的含义由活跃玩家集合决定；仍应行动的玩家不能因记录缺失而被静默跳过。

在本场比赛中，只有完整且确认正常的 tick 可以进入最终有效回放。若规则 step 抛出异常，本场为系统失败，不将不完整文件发布为正常完成的回放。

## 确定性要求

`step` 必须满足：相同规则发行、相同序列化状态、相同动作，产生相同下一状态和事件。

- 时间使用 tick，禁止规则读取现实时间、网络、进程环境和未显式输入的外部状态。
- 使用状态内保存的确定性 PRNG，不调用宿主 `Math.random()`。
- 初始状态保存初始化后用于未来随机行为的 PRNG 状态，不能只保存一个已被初始化过程消耗过的种子而忽略游标。
- 同时碰撞与圈地使用游戏明确规定的阶段与对称判定。
- 整数网格逻辑优先使用整数，不依赖动画插值或显示帧数。
- 状态、动作和事件均可显式序列化，不依赖对象原型、Map 的隐式编码、函数、时间对象或内存地址。
- 对冲突遍历使用固定次序；排序比较器和胜负判定不能依赖 locale 或宿主时间。

玩家代码的随机性和资源超限已经体现在最终记录的动作中。回放不再模拟其随机调用或判断它是否超时。

## 回放结构

回放使用下列完整协议。文件流式写入并用 gzip 压缩，文件名为 `<matchId>.json.gz`。`State`、`Action` 使用对应游戏的 schema；圈地状态字段见 [圈地规则](../designs/paper.md)。

```ts
type Replay<State, Action> = {
  formatVersion: 1;
  matchId: string;
  game: {
    id: string;
    release: string;
    botProtocolVersion: number;
    engineCompatibility: string;
  };
  players: Array<{
    id: string;
    slot: number;
    name: string;
    official: boolean;
  }>;
  config: JsonObject;
  resolvedLimits: ResourceLimits;
  initialState: State;
  ticks: Array<{
    tick: number;
    actions: Record<string, Action>;
    errors?: Record<string, ExecutionError>;
    logs?: Record<string, Array<{ level: LogLevel; message: string }>>;
    logsTruncated?: Record<string, true>;
    resources?: Record<string, { cpuUsedUs?: number; memoryBytes?: number }>;
  }>;
  result: {
    reason: string;
    completedTicks: number;
    players: Array<{ id: string; rank: number; score: number }>;
  };
  finalStateHash: string;
};
```

`JsonObject`、`ResourceLimits`、`ExecutionError`、`LogLevel` 由 protocol 导出；日志级别为 log、info、warn、error、debug。玩家 ID 对应固定席位，不能通过数组的偶然遍历顺序推断。initialState 必须完整，不能使用空地图或省略字段的展示占位作为正式回放。

resources 只保存实际取得的测量值，没有测得的数据直接省略，不把 0 当作未知值。服务端不写 logs、logsTruncated；本地写入受限日志，达到上限用 logsTruncated 标记。

### 回放校验

读取时先检查格式和可信发行，再检查配置、初始状态、参与者与动作的 schema。tick 必须从 0 连续递增；每个 tick 恰好包含当时所有可行动玩家的动作，不能缺失、重复或引入非参赛者。错误和日志不能代替动作。

重演首次返回终局时必须恰好耗尽动作记录，完成 tick 数、名次、得分和 finalStateHash 均需与保存结果一致。缺少终局、终局后仍有动作或校验失败时拒绝将文件展示为有效比赛。玩家输入的回放也不能要求播放器加载未注册的任意代码。

### 权威数据

规则发行信息、实际配置、完整初始世界和有序动作足以重建比赛。保存实际初始世界，不能仅依赖未来可能改变的地图生成器重新生成。

结果是方便查询的缓存摘要，应与重演结果一致。finalStateHash 保存最终状态的 SHA-256 摘要用于重演校验；编码时按 UTF-16 码元顺序递归排列对象键、保持数组顺序，使用 JSON 的字符串与有限数字编码，不使用 locale 排序。所有输入按严格 JSON 数据规则校验和序列化，数字 -0 归一化为 0。它是校验信息，不是每 tick 世界快照，也不是证明比赛未被篡改的完整机制。

### 诊断数据

`errors` 在本地与服务端都可存在。没有错误时省略。错误仅用于显示，不由播放器再次将动作改为默认动作：回放中的 `actions` 已经包含当时真实使用的默认动作。

`logs` 仅本地生成，缺省表示没有日志数据，不推断为执行成功。每条日志保留输出次序，超限截断标记可以作为诊断记录。可选资源用量是观察信息，不能反向影响回放规则。

### 不保存的数据

- 玩家源码、编译后的玩家字节码和历史代码引用。
- 玩家 JS 堆与调用栈快照。
- 每 tick 的完整世界快照。
- 每 tick Memory 快照；实时本地调试通过独立诊断通道查看，不写入标准回放。
- 可由规则重新生成的常规动画事件。

错误中的受限文本堆栈不等同于保存执行调用栈对象。

## 兼容性

回放格式版本与游戏规则发行标识分开管理。游戏规则修改或底层引擎行为改变时，需要明确新的发行标识，不能用最新版静默播放旧回放。

需要支持历史发行时，显式保留其可信规则包、必要引擎兼容实现和对应 renderer，供对应回放使用；玩家开发包只提供当前最新内容。已注册发行由 `apps/web/src/games/replays.ts` 与各游戏 manifest 定义。仅提示词和开发资料变化时保持游戏发行不变，开发包内容摘要不参与回放加载。发行清单明确回放所需的组件组合。缺少兼容版本时清晰提示不支持，不能展示可能错误的结果。

这是软件发行管理，不是保存玩家历史代码。首版只需随平台维护已发布的本地包和注册表，不需要远程插件市场或在打开回放时任意下载并执行文件内指定的代码。

## 播放与跳转

播放器从初始状态开始快速运行 step，获得逐 tick 世界。暂停、倍速和逐帧动画不影响 step 的计算结果。

播放器首次演算时每 50 tick 在内存中缓存一次世界状态。跳转到 tick N 时从最近的已有缓存或初始世界继续演算；圈地最多 500 tick，因此包括 S0 最多保留 11 个缓存状态。通用播放器始终保留 S0，另最多缓存 15 个中间状态，超过后按最近使用策略淘汰，避免其他长局游戏随 tick 无限增长。缓存不写入标准回放，向后跳转不反向执行动作。

重新结算时即时生成移动、圈地、尾迹切断、淘汰等事件，由 renderer 插值播放。跳转时可跳过动画，直接显示目标世界。

缓存另设 32MiB 序列化字节上限；超过时淘汰中间检查点，始终保留 S0，初始世界本身超过预算则拒绝建立会话。播放器不保存整场逐 tick 世界，仅保留有界检查点和当前、前一世界。

网页 `/replays` 通过 `@si-arena/player/browser` 在浏览器内读取 gzip、严格 UTF-8 和 JSON，限制压缩输入 32MiB、解压后 64MiB。读取或校验可取消；匹配游戏 ID 与完整发行标识的可信注册后，先完整重演并核对终局与摘要，再开放画面和诊断。回放文件不上传，不要求玩家源码或平台 API 在线。

通用 Vue 调度器以每秒 10 tick 为基准，提供 0.5/1/2/4/8 倍速、单步与错误导航。默认暂停，后台标签页暂停；用户跳转时暂停并显示精确世界。错误导航将输入 tick t 映射为已完成 t+1 tick，日志与观察面板同样关联输入 tick。地图世界按 tick 离散跳变，调度器在 tick 间隔内以连续动画进度驱动 renderer 重绘，进度随倍速缩放；跳转与单步直接显示稳态世界，暂停定格当前画面。接口和命令见 [播放器说明](../../packages/player/README.md)。

## 保存流程

worker 在执行期间将动作写入私有临时文件或有界流，不在内存中无限积累整场日志。完成时封装结果、压缩、验证完整性，保存到包含执行标识的不可覆盖候选路径。只有数据库成功提交 completed 并引用该文件后，才对外提供最终回放。候选路径为 `REPLAYS_DIR/candidates/<matchId>-<executionId>.json.gz`，终稿为 `REPLAYS_DIR/<matchId>.json.gz`：结算事务确认执行权后将候选硬链接为终稿，不覆盖任何已有文件。若发布成功后数据库回滚，重试仅接受与本次候选设备号、inode 均相同的已有普通文件，其他已有目标一律拒绝；发布后在支持的平台上同步终稿目录，确保文件引用持久化后再提交数据库。

可靠保存最终回放后，才在数据库事务中提交比赛终态和对应模式的成绩。文件与数据库不能使用同一事务，需要通过唯一比赛 ID、确定的文件引用、幂等提交和孤立文件清理处理边界，详见 [数据模型与 API](data-model-and-api.md)。
