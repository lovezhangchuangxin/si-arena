# 本地开发与调试

## 下载内容

玩家通过 `@si-arena/cli` 按游戏初始化开发目录，也可直接使用游戏页面的 ZIP 下载入口；两种方式获取同一发行产物。

每个游戏页面提供独立开发包，包含：

- 对应游戏规则包、引擎、沙箱执行器和本地工具。
- SDK 类型定义、基础动作 API、统一参赛提示词和说明。
- 官方示例 bot 源码与玩家代码模板。
- 可视化播放器、本地调试界面和启动说明。
- 软件发行信息、依赖声明、锁文件和必要许可证。

用户不需要克隆完整 monorepo，不需要账号、平台 API、数据库或模型 API 密钥。安装依赖可能需要网络，但运行本地比赛不依赖平台在线服务。

## 操作流程

以下以圈地为例，将示例域名替换为实际平台地址；独立开发包提供以下命令：

```sh
npx @si-arena/cli@latest init paper ./paper-bot --server https://arena.example.com
cd paper-bot
pnpm install --frozen-lockfile
pnpm arena dev --bot ./bot.js
pnpm arena run --bot ./bot.js --matches 20 --seed 42
pnpm arena replay ./replays/实际文件名.json.gz
```

初始化命令也支持 `pnpm dlx @si-arena/cli@latest init paper ./paper-bot --server https://arena.example.com`。它下载并解压开发包、固定发行与资源配置，不自动安装依赖、不覆盖非空目录，也不创建线上比赛。始终获取最新包，不提供发行或修订选择。

已有项目运行 `pnpm arena update`，再执行 `pnpm install --frozen-lockfile`。服务器地址由初始化记录，也可通过 `--server` 指定；直接解压 ZIP 后首次更新需要指定服务器。更新保留 bot.js、research/、回放、自定义对手和其他用户文件；更新的平台文件若被本地修改则备份到 .arena-backups/。下载校验失败不改项目，安装中普通错误会回滚；相同内容不重复写入。游戏规则、SDK 和本地工具随服务器开发包获取，游戏不公开发布到 npm。

玩家可以复制游戏页「开发资料」区的 AI 安装提示词，交给本地编程 Agent 完成环境准备和策略研究。网页按当前游戏与站点地址生成初始化命令，要求保留已有项目与研究成果；统一参赛提示词定义各游戏的机制和验证方法。网页提示词随源码提供，开发包内 PROMPT.md 随开发包构建固定。公共流程维护在 packages/development/RESEARCH.md，与游戏专属提示词通过同一函数组装。修改资料后重新构建更新当前开发包，不改变游戏 release、botProtocolVersion 或旧回放的规则身份。

开发包 README 说明安装、文件用途、比赛结果、更新和上传；PROMPT 说明规则、策略思路和研究流程；SDK 提供接口参考。

文档需区分局内得分 score、最终名次 rank 和线上排位分。本地比赛不影响线上排位。批量胜负只统计单独第 1、并列第 1 和其他名次，多人比较还要查看每场名次。执行错误数包含所有玩家，可在回放中按玩家 ID 查找；命令成功退出不表示每个 tick 都执行成功。

### 研究与交付

公共研究要求只维护在 [RESEARCH.md](../../packages/development/RESEARCH.md)，各游戏补充规则与专属验证方法。网页和 ZIP 都交付组装后的完整 PROMPT，不要求玩家寻找仓库文件。

研究在用户预算内进行，保留本地候选、历史最佳和独立验证记录。对抗游戏用多种对手与固定条件比较；单人游戏分别运行候选和基线，用相同种子比较 score，不传 --opponent，也不把固定第 1 名当作胜率提升。交付 bot.js 与真实报告，上传和线上开赛仍由玩家主动操作。

开发包包含 botProtocolVersion，与网站参赛提示词一同显示。不兼容升级时用户重新获取当前开发包并上传适配代码；兼容升级不强制重传，排位分均保留。批量运行指定的每个本地 bot 同样接受语法和入口协议检查。

### 调试、批量运行与回放

`dev` 打开本地调试页面；对抗游戏默认加入官方 bot，也可指定本地对手，单人游戏独立运行。命令启动即自动开局：比赛在后台整场运行，页面轮询显示 tick 进度，完成后载入完整播放器逐步查看。修改代码后可以重新开局，不在比赛中途热替换策略；重新开局默认复用同一种子（确定性复现），也可以换浏览器生成的随机种子，任何时候都可以中止当前局重开——重开会重新读取并校验源码，语法或入口错误在页面显示原因并保留上一场结果。`dev` 依赖开发包内置的调试页资源，服务只监听 loopback，不保存回放文件；需要留存时以相同种子运行 `run`。

`run` 批量运行并输出比赛摘要和回放；对抗游戏默认使用官方对手，单人游戏没有对手。批量模式每场重置 Memory。种子相同并不保证不同硬件上的 CPU 超时行为相同。

`replay` 不加载玩家代码，只读取回放及匹配的软件规则版本。

终端独立校验使用 `arena replay <file> --verify`，加 `--logs` 可输出玩家日志与执行错误，所有诊断在完整重演通过后显示。运行命令输出 JSON Lines，包含发行与限额、每场结果、回放路径及整批胜平负；操作见 [CLI 使用说明](../../packages/cli/README.md)。

## 日志

本地工具捕获 `console.log/info/warn/error/debug`。每条日志关联比赛、tick、玩家与输出顺序，打印时生成内容快照，不保留可变对象引用。

本地日志保存到回放。发生异常或超限之前已经捕获的日志仍然保留，即使当 tick 动作与 Memory 被丢弃。实现上需要将日志流式送到外部有界缓冲区，不能等沙箱正常结束后才一次性取出。

必须限制单条大小、每 tick 条数与字节数以及整场日志大小。超过上限后截断并提示，不因日志溢出改变默认动作或淘汰玩家。日志序列化也受执行预算约束，避免恶意对象、循环结构和巨量输出阻塞运行器。

服务端提供相同 console 接口，但不收集、不保存、不转发玩家日志；用户代码不能借它写入业务服务日志。

## 错误

本地和服务端的已完成回放均可记录玩家运行异常、CPU 超限、isolate 堆超限、Memory 超限和非法动作。整个比赛进程崩溃或失去响应属于系统失败，不承诺生成可播放回放，不能把它写成普通玩家的 tick 错误。

本地运行异常包含错误名称、消息和指向玩家源码的堆栈与行列位置；无法取得行列时明确省略对应字段。诊断必须有长度上限，不能依赖玩家抛出的任意对象可正常序列化。进程意外退出无法确定是否因内存导致时，只报告比赛执行失败，不能误报为已确认的内存超限。

错误处理是跳过当前 tick 的玩家执行结果，下一 tick 再次调用入口，不是从报错位置继续执行。重复错误可以重复发生，不由平台替玩家修复代码。

## 调试页面

已保存的 `.json.gz` 回放可在网站 `/replays` 打开。文件只在浏览器内读取，完整校验通过后播放；不上传、不创建比赛、不执行 bot，也不依赖 API 在线。回放页提供下述地图、时间轴、日志、错误与观察功能。实时调试会话的 Memory 属于独立本地运行服务，不从已保存回放恢复。

- 地图、时间轴、播放控制、逐 tick 前进和按需跳转。
- 按玩家和日志级别筛选，跳转到上一个或下一个错误 tick。
- 查看当 tick 观察、有效动作、错误及资源消耗。
- 查看实时本地会话中的 Memory 提交前后内容。

在线比赛隐藏 console 日志工具；本地文件只有实际包含日志或日志截断记录时才显示筛选面板，否则显示无日志提示。实时本地调试保留日志面板与 Memory 对比。三种来源共用地图、播放控制、执行错误、动作与观察界面，不改变回放校验和执行规则。

本地文件与实时调试的时间轴、播放控制位于地图上方，滚动地图时工具栏保持可达。在线参赛工作台将画面按可用高度等比缩放，控制条放在画面下方，诊断放在右侧对局 tab。逐 tick、倍速与精确跳转集中展示，只有存在执行错误时才显示错误跳转按钮。

Memory 仅在实时本地调试会话中展示，不写入回放，避免每 tick 保存大对象。打开已保存的回放时隐藏 Memory 面板，不能为了显示 Memory 而重新执行代码。

## 一致性边界

本地与服务端使用相同版本的规则、引擎、SDK 和沙箱代码，同样的输入和动作应得到相同世界状态。CPU 超限依赖硬件，日志收集也有成本，不能承诺本地运行耗时与线上完全一致。

本地工具必须明确展示当前发行版本和限制配置。下载包使用平台指定的完整配置；当前 CLI 没有玩家预算覆盖选项。开发者自定义可信注册并调整限额时必须明确展示差异，不代表线上预算改变。
