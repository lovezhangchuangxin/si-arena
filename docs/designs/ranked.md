# 排位与匹配

## 触发条件

比赛必须由某个用户主动发起。用户上传代码、登录、下线或后台时钟变化均不创建比赛。上传后显示“匹配”入口，由用户另行操作。

发起者必须在该游戏提交与当前代码协议兼容且体积合规的代码。其他合格用户即为可选对手，无需在线、进入等待队列或确认邀请。不兼容升级后旧代码暂停参赛并提示重新上传；兼容升级继续使用，排位分均保留。

比赛类型在创建时固定：

| 类型             | 产生方式                                         | 结算与统计                                               |
| ---------------- | ------------------------------------------------ | -------------------------------------------------------- |
| `ranked` 排位    | 双人游戏主动匹配到普通用户                       | 双方 Elo 与胜平负、比赛数都更新，包括被动参赛者          |
| `practice` 练习  | 双人游戏指定对手，或没有普通候选时回退到官方 bot | 记录本场名次、得分，不改变累计排位与战绩                 |
| `boss` Boss 挑战 | 双人游戏挑战部署方私有 bot                       | 不改变排位；个人页展示 Boss 挑战次数与获胜次数           |
| `arena` 竞技场   | 用户开启游戏的多人竞技场                         | 普通选手按名次逐对计算 Elo，累计场次、冠军次数与名次总和 |
| `solo` 单人挑战  | 单人游戏主动开局                                 | 累计场次并更新历史最高分，不更新 Elo 或胜平负            |

官方账号与 Boss 均不进入排行榜。多人竞技场中的官方 bot 不产生计分对，但普通选手之间仍正常计分。

后台只处理用户已经创建的匹配请求，不自行产生新的竞技请求。

## 双人匹配流程

1. 验证身份、代码是否存在以及请求是否重复。
2. 在相同游戏的非本人普通用户中选择对手，见下方规则。
3. 没有任何合格的普通用户时，立即与官方 bot 进行一场练习，不等待真人上线。
4. 写入比赛任务，返回比赛 ID。
5. worker 开局时读取双方最新代码，开始执行。
6. 排位赛完成后同时更新双方排位分。

“立即匹配”意味着立即确定可用对手并创建任务；服务器资源繁忙时仍可能短暂等待 worker，不承诺零排队延迟。

对手只从合格的普通用户中选择，规则如下：

1. 发起者最近 5 场已完成排位赛的对手标记为“近期对手”。存在其他候选时，排除近期对手；全部候选都是近期对手时，只排除最近一场的对手；只剩一名候选时允许重复。
2. 先在分差 250 以内的剩余候选中选择绝对分差最小者。
3. 250 以内没有候选时逐级放宽到 500、1000，最后不设上限，仍选分差最小者。
4. 最小分差并列时随机。

任何路径都排除本人。

## 双人练习与 Boss

在排行榜或比赛记录中可以选择一名合格选手（包括官方 bot）直接挑战。对方无需在线。指定普通或官方对手的挑战总是练习赛：不改变双方排位分，不计入战绩，不出现在排行榜依据中，但会出现在双方的比赛记录里并标注“练习”。挑战与主动匹配共用“同一游戏只有一个未完成的主动请求”限制。Boss 挑战使用独立类型，源码不公开，仅在部署方安装该游戏 Boss 后开放。

## 多人竞技场与单人挑战

竞技场开局者必须有合格代码并占第一席，其余席位按该游戏的排位与平分规则选取；人数不足时官方 bot 只补一个席位。数据库保证每个游戏至多一场未完成竞技场比赛。席位数、人数下限和历史保留数见对应游戏设计与 manifest。

单人游戏只让发起者入场，不接受指定对手或 Boss 参数。比赛完成后更新 `bestScore = max(旧 bestScore, 本局 score)`，`matchesPlayed` 加一；失败比赛不刷新纪录。无需等待对手，但仍需等待 worker 执行。

## 排行榜

对抗游戏的排行榜反映排位分：任何一场排位赛结算后，双方的排位分立即生效，被动成为对手的一方同样计入。网页在排行榜可见时定期刷新，自己的比赛结束后立即刷新。单人榜单按 `bestScore` 降序，同分并列且按用户 ID 稳定展示。所有榜单均排除官方 bot 与 Boss。

## 官方 bot

- 官方账号在每个游戏有一份独立代码。
- 源码与本地开发包一同公开，运行环境与普通选手相同，不读取隐藏状态。
- 1v1 与官方 bot 的比赛都是练习，不改变任何人的排位分；竞技场中官方 bot 只补一个席位，本身不产生计分对。官方 bot 不进入排行榜。
- 可以同时作为多场独立比赛的对手，每场使用独立的沙箱和 Memory。
- 官方身份由系统字段标记，特殊用户名只负责展示。

每个游戏发布时必须提供可运行官方 bot。双人游戏用它保证首个真实用户有对手；单人游戏用它作为本地得分基线。

## 得分与排名

| 概念       | 定义                                                   |
| ---------- | ------------------------------------------------------ |
| 局内得分   | 由游戏规则计算，例如领地面积                           |
| 比赛名次   | 由游戏根据淘汰、得分、平局等规则生成                   |
| 排位分     | 平台根据名次与对手排位计算，按游戏独立                 |
| 历史最高分 | 单人游戏已完成比赛的最高局内得分，不是 Elo             |
| 排行榜     | 对抗游戏按排位分，单人游戏按历史最高分；系统账号不入榜 |

对抗游戏排位使用 Elo；本节公式不用于单人挑战。两人局中，A 的预期得分为 `EA = 1 / (1 + 10 ** ((RB - RA) / 400))`；实际得分 `SA` 在胜、平、负时分别为 `1`、`0.5`、`0`。更新 `RA' = RA + K * (SA - EA)`，B 对称计算。

初始排位分为 1000，K 为 32。内部使用 `numeric(12,6)`，每对选手先把 A 的变化四舍五入到 6 位小数，再以相反数更新 B，确保单次变化之和为 0。排位详情显示 2 位小数，名次按内部精确分数计算；精确分数相同显示并列。双人榜单按用户 ID 稳定展示，竞技场的平分展示顺序由该游戏规则指定，不改变并列名次。

多人游戏将名次转换为每对计分选手的胜、平、负，使用 `K / (计分人数 - 1)` 计算每个无序选手对的变化，保留 6 位小数后对双方分别加减，再累加所有对手的变化；计分人数不含官方 bot 与 Boss，全部变化之和为 0。相同名次按平局计算。双人游戏使用上述两人公式；多人竞技场使用逐对公式。计分人数少于 2 时没有计分对，Elo 不变。

## 并发与重复请求

- 主动发起使用幂等请求标识，网络重试返回同一比赛。
- 限制同一用户在同一游戏只有一个未完成的主动请求，避免连续点击重复创建任务。
- 数据库对未完成主动请求建立部分唯一索引，不能仅用“先查询再插入”处理并发；不同请求同时到达时也只能创建一场。
- 被动成为对手不依赖在线状态，可参与多场独立比赛；总执行量由 worker 并发限制控制。
- 结算按稳定顺序锁定计分参与者的成绩行，以结算时的排位计算变化，避免并发覆盖。
- 每场比赛最多结算一次；任务重投递不能重复加减分。
- 官方 bot 不受“同一时间只能被一个人挑战”的限制。

选择对手使用创建请求时读取的排位，不承诺长时间排队后的分差仍相同。创建比赛固定参赛者与发行，worker 开始执行时读取最新源码；只有这次读取之后的上传才不会影响本场。上传不重置排位或最高分。

## 失败分类

玩家 JS 异常、超时或超限属于比赛内事件：转换为当 tick 默认动作，正常比赛和计分，不能因主动抛异常逃避败局。

规则引擎崩溃、主 worker 丢失或回放无法可靠保存属于系统失败：本场不更新排位，不伪造胜负。只重试持久化和结算等幂等操作，不使用已经被替换的代码重新跑一场并冒充原比赛。

比赛排队期间若用户的新代码不再兼容本场已冻结的发行或超过其源码上限，开局检查使任务失败、不计分，并提示重新主动匹配，不恢复旧代码。
