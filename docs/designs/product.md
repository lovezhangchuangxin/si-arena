# 产品与参与流程

## 目标

让用户把 AI 编写的策略程序放入直观、可视化的小型游戏中参赛，通过胜负、名次或单人得分比较策略表现，并根据反馈继续改进。

比赛运行的是已生成的程序。程序成绩体现规则理解、策略实现和代码质量等因素，不宣称等同于模型临场推理能力或通用能力。模型、提示词和时间预算由用户自行选择及约束。

## 玩家与选手

“玩家”是平台用户。“选手”是该用户在某个游戏中提交的最新程序。同一用户在不同游戏中的代码、排位分和局内得分互不影响。

平台为每位用户每个游戏保存一份最新代码。用户可以反复修改并替换，但不能查看或回滚平台保存的旧代码。比赛记录和回放按各模式的保留规则保存，不等同于代码版本管理；竞技场只保留最近若干场。

官方账号具有不可由普通用户设置的官方标记，显示特殊名称或徽章。每个游戏必须提供该账号的官方示例 bot，公开源码。双人游戏中与官方 bot 的比赛是不计分的练习；竞技场的官方席位不参与 Elo 计算；单人游戏的官方 bot 供本地独立运行和比较。官方 bot 不进入排行榜。首版采用一个官方账号，不要求设置多个难度档位。

部署方可以为双人游戏安装一个私有的 Boss bot 供玩家挑战：源码不公开，挑战不计分，击败 Boss 的次数显示在玩家的个人页面。

## 参赛模式

| 模式       | 游戏                       | 发起后发生什么                                                             | 榜单依据       |
| ---------- | -------------------------- | -------------------------------------------------------------------------- | -------------- |
| 双人对抗   | 圈地、坦克                 | 匹配一名普通选手，无人可选时与官方 bot 练习；也可指定对手练习或挑战 Boss   | Elo 排位分     |
| 多人竞技场 | 圈地大逃杀、贪吃蛇、炸弹人 | 开局者入场，其余席位按游戏的榜单规则选取；每个游戏同时只运行一场竞技场比赛 | 按名次计算 Elo |
| 单人挑战   | 俄罗斯方块                 | 只创建发起者的一人局，不选择对手                                           | 历史最高分     |

所有模式都由用户主动发起，都可能等待 worker 容量。完整计分与并发约束见 [排位与匹配](ranked.md)。

## 参与流程

用户使用用户名和密码注册登录。浏览游戏、下载开发包、查看官方 bot 和公开回放不要求登录；上传代码和主动匹配要求登录。

1. 浏览游戏页面，了解规则、胜负条件、动作接口、执行限制和错误行为。
2. 复制统一参赛提示词，下载 SDK、引擎、游戏包、官方 bot 和本地工具。
3. 在本地使用任意 AI 工具编写 JS，运行本地比赛并查看日志和回放。
4. 通过「上传策略」或「更新策略」选择 JS 文件，或拖放单个文件后自动上传。平台检查体积、编码、语法和约定的代码格式，通过后替换最新代码；不运行一场平台试跑，也不自动创建排位。失败保留原策略；网络中断导致结果不明时读取当前源码核实，未确认前暂停匹配，允许核实状态或重试同一份上传。
5. 用户主动发起匹配、挑战或竞技场。需要对手时，系统按模式选择，无需对手在线或确认。
6. 后端执行比赛，用户查看状态、结果和可视化回放。用户离线不取消已创建的比赛。
7. 用户在本地修改代码，再上传并主动参赛。

只有用户主动发起参赛才会创建新的线上比赛。后台领取并执行显式创建的任务，可重试幂等保存与结算；主运行器丢失世界与代码快照后不透明恢复原比赛，也不能定时拉取选手开新比赛。

## 页面职责

| 页面           | 必需内容                                                         |
| -------------- | ---------------------------------------------------------------- |
| 注册与登录     | 用户名和密码注册登录、登出、修改密码                             |
| 游戏列表       | 游戏简介、进入游戏的入口                                         |
| 游戏详情       | 规则、统一提示词、SDK 与下载入口、官方 bot 源码                  |
| 我的该游戏选手 | 最新代码上传、排位分或最高分、主动参赛入口、最近比赛             |
| 游戏排行榜     | 按游戏展示排位分或最高分、比赛数；定期刷新，不含官方 bot 与 Boss |
| 赛场内比赛     | 参与者、执行状态、名次、局内得分、排位分变化、回放               |
| 本地调试页面   | 只随本地工具启动，支持日志、错误、Memory 与资源信息              |

无需在线代码编辑器、服务端试跑、模型 API 配置或模型认证流程。网页中的代码展示以官方示例和用户自己的最新代码为主，首版不开放其他普通用户代码下载。

## 网站布局与操作

### 大厅、账号与公共页面

顶部提供大厅、各游戏、排行榜、本地回放和账号入口。大厅按目录展示游戏，个人记录与榜单入口按已登录状态展示。网站采用深色主题，中文使用系统字体，数字与等宽字体自托管。

| 路径                        | 用途                                               |
| --------------------------- | -------------------------------------------------- |
| `/`                         | 游戏大厅                                           |
| `/account`                  | 个人成绩、Boss 战绩、修改密码和退出登录            |
| `/leaderboard?game=:gameId` | 按游戏切换榜单，单人游戏显示最高分                 |
| `/games/:gameId/arena`      | 多人竞技场状态、阵容预览与保留的比赛               |
| `/replays`                  | 浏览器内打开本地 gzip 回放，不上传文件、不执行 bot |

旧 `/royale` 跳转到 `/games/royale/arena`。榜单可见时每 10 秒刷新，自己的比赛结束后立即刷新；竞技场运行中每 3 秒、空闲时每 15 秒查询。比赛状态轮询与退避见 [API 契约](../architecture/data-model-and-api.md#比赛历史详情与回放)。

登录凭据保存在浏览器 localStorage；会话过期需重新登录，退出撤销当前会话，改密撤销全部会话。只有本人可读取自己的最新源码，比赛结果和回放允许公开查看。

### 参赛工作台

游戏页采用固定画面的参赛工作台。PC（宽度至少 1024px）占满视口，页面本身不滚动；左栏更宽，持续展示游戏画面，棋盘按剩余宽高等比缩放。右栏顶部固定「玩法 / 对局 / 我的比赛 / 排行榜 / 开发资料」导航，中间内容独立滚动，底部固定排位、策略状态、上传与匹配操作。规则、长代码或资料不会把参赛操作推到视口外。

未选择比赛时，左栏使用注册的可信游戏定义和 renderer 绘制静态初始世界，不执行 bot、不推进 tick，也不创建比赛。选择历史比赛或主动匹配后，同一画面区展示该场状态；完成后加载暂停的回放，播放、单步、倍速和时间轴位于画面下方。右栏切换内容不销毁比赛或播放器，播放进度与速度保持不变。收起比赛回到静态画面。

玩法上方展示规则和折叠的执行限制，下方展示本人当前源码（只读）；上传选择文件后自动校验并替换，操作区在其他 tab 下仍然可用。对局展示当前比赛的结果、各参与者成绩、适用时的排位变化、折叠的比赛信息、当前比分和 Tick 诊断；公开旁观者不显示相对自身的胜负。系统失败、玩家执行错误与回放加载失败分别呈现。完成或失败后刷新参赛状态，可直接继续主动匹配或更新策略。

### 路由与比赛记录

地址 `/games/:gameId?match=:matchId` 可刷新与分享，并默认打开对局。`tab=play` 或 `tab=match` 保留对应内容选择；历史、排行榜和开发资料继续使用可直接访问的子路径，切换与分页保留比赛选择。旧 `/matches/:matchId` 链接自动转入对应工作台，原规则路径与开发资料锚点仍可访问。比赛记录按当前用户和模式展示胜负、名次、单人得分或执行状态，并显示适用的对手、排位变化与时间；主动和被动比赛都包含在内。只有本人未完成的主动请求显示「查看当前比赛」，被动参赛不阻止主动匹配。

### 开发资料与窄屏

开发资料保留初始化命令、AI 安装提示词、开发包下载、提示词、SDK 和官方代码。长提示词默认折叠，复制和下载入口直接可用；AI 安装提示词按当前游戏与站点地址生成，支持复制与展开全文，覆盖环境准备、初始化、依赖安装、预算内策略研究与独立验证。研究预算、独立验证与交付要求由 [公共研究流程](../../packages/development/RESEARCH.md) 统一维护，网页安装提示词引用组装后的 PROMPT。

窄屏改为画面在上、导航与内容在下，页面自然纵向滚动；参赛操作固定在屏幕底部，并为内容预留等高空间，错误展开后也不会遮住底部内容。导航支持键盘左右键、Home 与 End 切换。
参赛工作台优先展示操作、数据、必要状态与错误，避免重复展示大厅的入门介绍。

## 代码更新边界

开始执行比赛时，worker 一次性读取所有参赛者的最新代码，并固定用于本场比赛。之后发生的上传仅影响未来开局。

本场代码只在执行生命周期内暂存，比赛结束后释放，不写入回放或代码历史表。比赛开始后上传新代码，不重启正在进行的比赛。排位或最高分属于用户在该游戏的选手身份，不绑定历史代码版本，上传不会清零。

游戏发行与玩家接口兼容版本分开。兼容升级继续使用现有代码；不兼容升级后旧选手保留代码、排位和比赛记录，但暂停主动与被动参赛，页面提示重新上传。代码的接口兼容标识是当前代码的一项元数据，不是历史源码版本管理。

比赛在创建时固定发行，开局时读取最新代码。排队期间若代码已换成与该发行不兼容的代码，任务失败、不计分，用户重新主动匹配；系统不恢复旧代码，也不把本场悄悄切换为其他规则。

## 非目标

- 严格模型评测、统一生成预算与模型 API 集成。
- 自动开赛、自动训练或自动改写用户代码。
- 玩家历史代码管理与回滚。
- 跨游戏总榜或共享排位分。
- 首版实时联机操控、平台试跑、插件市场和热安装远程游戏。
