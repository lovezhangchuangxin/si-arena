# 圈地大逃杀

## 核心玩法

大逃杀是独立的游戏 `royale`，与 1v1 圈地分别上传代码、分别排名，玩家接口互不兼容。规则延续圈地：离开领地留下尾迹，回到领地圈下围住的格子。区别在于多人同场、**被杀即出局**，以及随淘汰收缩的安全区。最后存活的玩家获胜。

全服只有一个大逃杀竞技场。任何登录用户都可以开局；同一时间只运行一局，跑完后所有人观看回放。服务器只保留最近 3 局。

## 入场

开局时选出最多 5 名选手：

1. 开局者必定占用第一个席位；开局者需在 `royale` 上传与当前接口兼容、体积合规的代码，否则不能开局。
2. 其余席位从其他普通用户中选出，不含官方账号：按大逃杀排位分降序；排位分相同按 1v1 圈地排位分降序；仍相同按用户 ID 升序。
3. 不足 5 人时由官方 bot 补一个席位，官方 bot 不参与计分、不进入排行榜。
4. 入场人数少于 2 人时不能开局。

创建比赛时固定入场名单和游戏发行；worker 开始执行时一次性读取所有参赛者的最新代码。读取之后的上传只影响后续开始执行的比赛，排队期间的上传仍可能影响本场。

## 地图与开局

| 项目     | 规则                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 人数     | 2–5 人                                                                                |
| 地图     | 正方形，边长 `max(20, ceil(sqrt(320 × 人数)))`：2 人 26、3 人 31、4 人 36、5 人 40    |
| 时长     | 最多 800 tick                                                                         |
| 初始领地 | 每人 3×3                                                                              |
| 出生点   | 以地图中心为圆心、半径 `0.32 × 边长` 的圆上等角分布，起始角由种子决定，取点所在的格子 |
| 席位     | 按入场顺序编号 0–4；用种子打乱席位与出生点的对应关系                                  |
| 视野     | 完整地图                                                                              |

坐标、数组布局与圈地相同：`index = y * width + x`，`-1` 表示无归属，`0`–`4` 表示席位。

## 动作与结算

动作与圈地相同：`move` 上下左右或 `idle`，每 tick 所有存活玩家同时结算。

一个 tick 内按以下顺序判定，结果全部基于本 tick 开始时的世界：

1. **越界**：移动出地图的玩家死亡。
2. **相撞**：两个及以上头部进入同一格，全部死亡；两人互换位置，双方死亡。
3. **切尾迹**：头部进入某存活玩家的尾迹格，该尾迹的主人死亡；进入自己的尾迹也会死亡。`idle` 停在自己当前头部格不算踩自己的尾迹。踏入者本 tick 因越界以外的原因死亡时，切断照样生效。
4. **移动与留迹**：存活玩家移动；离开自己领地的格子留下尾迹。本 tick 新画出的尾迹从下一 tick 起才能被切断。
5. **圈地**：头部回到自己领地且有尾迹的玩家闭合。闭合者以自己的领地和尾迹为屏障，从地图边缘四邻接洪泛，走不到的格子中不是它原有领地的部分是它的圈占。只被一名闭合者圈占的格子归该闭合者；被多名闭合者同时圈占的格子保持原状。任一圈占格上的他人尾迹视同被切断，尾迹主人死亡，即使该格因争夺没有易手；压在闭合者原有领地上的他人尾迹不受影响。闭合者清空尾迹；头部所在格被别人圈走、又没有尾迹的玩家在头部格留下一格尾迹。
6. **安全区**：若本 tick 需要收缩（见下节），先收缩；之后头部位于安全区外的玩家死亡。
7. **清理**：本 tick 死亡的玩家，其领地和尾迹全部变回无主地，头部移出地图。

同一玩家可能同时满足多个死亡原因，按 `boundary`（越界）、`head-collision`（同格相撞）、`head-swap`（互换位置）、`self-trail`（进入自己的尾迹）、`trail-cut`（尾迹被踩）、`enclosed`（尾迹被圈占）、`zone`（安全区外）的固定顺序全部记录。死亡玩家不再获得观察、不再执行代码。

## 安全区

- 安全区是居中的正方形，开局等于整张地图。
- 目标边长 `max(10, ceil(sqrt(320 × 存活人数)))`，存活人数变化时立即更新目标。
- 当前边长大于目标时，在 tick 编号为 10 的倍数的结算中（第 10、20、30… 个 tick）向内收缩一圈（边长减 2），直到不大于目标。是否收缩按该 tick 开始时的存活人数判断，因此有人死亡后最早在下一个 10 的倍数收缩。
- 收缩时，落到安全区外的领地和尾迹变回无主地，头部留在外面的玩家在同一 tick 死亡。安全区外始终是无主地。
- 观察中提供当前边长、目标边长、左上角格子和距下一次收缩的 tick 数（`10 - tick % 10`，不收缩时为空），玩家可据此规划。

## 结束与名次

- 存活人数不超过 1 时立即结束；存活者第 1 名。
- 到达 800 tick 时，存活者按领地面积排名，面积相同并列。
- 已死亡的玩家排在所有存活者之后，死得越晚名次越好；同一 tick 死亡的玩家并列。
- 所有玩家在同一 tick 同归于尽时全部并列第 1 名。
- 名次等于排在自己前面的人数加 1，并列者共享名次（如 1、1、3）。结果中的 `score` 为最终领地格数（死亡者为 0），结束原因为 `elimination`（存活不超过 1 人）或 `tick-limit`。

## 排位与排行榜

竞技场使用与 1v1 圈地相同的 Elo 体系：初始 1000，K 为 32。结算时把最终名次转换为每对普通参赛者的胜、平、负（名次靠前为胜，同名次为平），每对使用 `K / (普通参赛人数 - 1)` 计算，累加得到每人本局变化；内部保留 6 位小数，每局变化总和为 0。只有一名普通参赛者时没有计分对，排位分不变。

排行榜按排位分排序，同时显示参赛场次、冠军次数和平均名次；排位分相同的展示顺序按 1v1 圈地排位分（无记录按 1000）和用户 ID。官方 bot 不进入排行榜。系统失败的一局不计分。

## 观察与 SDK

观察包含 tick、上限、自身席位与 ID、地图（领地、尾迹）、安全区（当前与目标边长、左上角、距下一次收缩的 tick 数）、全部存活玩家的公开信息（ID、席位、头部位置、出生点、领地面积）、已出局玩家列表（ID、席位、死亡 tick 与原因）及上一 tick 的公开事件（移动、切断、圈地、缩圈、死亡）。玩家入口与圈地一致：`export default function tick({ game, Memory })`，通过 `game.self.move(direction)` / `game.self.idle()` 登记意图。完整接口见 [royale SDK](../../games/royale/SDK.md)。

资源限额与圈地相同：每 tick 20 ms CPU，执行出错时该 tick 使用默认动作并保留上次成功的 Memory。

## 历史保留

每局完成后，删除最近 3 局以外的大逃杀比赛记录和回放文件。排位分在结算时已经更新，删除记录不影响排位。
