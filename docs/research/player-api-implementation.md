# 游戏自定义基础动作 API 实施记录

本文是 paper@0.2.0 内部开发阶段的历史记录。以下 QuickJS、发行状态、测试数量与性能结果描述当时工作区；当前实现见 [沙箱设计](../architecture/sandbox.md)，当前玩家接口见 [SDK](../../games/paper/SDK.md)。

本次变更合并进尚未正式发布的 `paper@0.2.0`，玩家协议保持 v2，不把未发布期间的中间接口注册成历史发行。

## 玩家接口

玩家默认导出同步函数，接收 `{ game, Memory }`，返回 undefined。角色方法登记意图，入口正常结束后，包装器在同一预算内序列化规范动作与候选 Memory，由父进程游戏解析器验证后原子提交。执行异常、超限、非法命令或非法返回值都会丢弃该 tick 全部命令和候选 Memory，下一 tick 重建环境。

圈地只提供 `game.self.move(direction)` 与 `game.self.idle()`；未调用默认停留，重复调用以最后一次为准。地图和位置不会因调用而立即改变，双方仍统一结算。API 没有寻路、安全方向、威胁评估或扩张策略；官方 bot 自身包含所需算法。完整字段和示例见 [SDK.md](../../games/paper/SDK.md)。

game 每 tick 重新构建，嵌套公开数据冻结。旧角色方法持有旧 tick 的提交闭包，调用会锁定 INVALID_ACTION，即使 catch 后再调用合法方法也不能提交。成功 tick 间仍允许全局缓存，只有提交的 JSON Memory 用于失败恢复。

## 通用执行与游戏边界

引擎继续处理游戏定义的 JSON Action，不知道方向、地图、角色、单位数量或命令类型。SDK 的可信自包含 ESM 默认导出 `(observation, { submit, reject }) => game`。模块在常驻环境中加载一次，工厂每 tick 在玩家代码前构造视图并初始化该游戏默认意图；submit/reject 都是 QuickJS 内的闭包，不是宿主回调。

游戏可以在私有集合中累积多个单位的不同命令，自行决定覆盖、并存和校验规则，再通过 submit 更新规范动作集合。提交不会产生逐命令 IPC，最终仍一次性输出有界 JSON。reject 锁定玩家命令错误；工厂异常是系统失败。平台没有增加 RTS、攻击或采集等实际游戏，仅以沙箱测试游戏验证多角色与自定义命令集合。

可信模块初始化、每 tick 输入冻结及视图构建不计入玩家 CPU，仍受墙钟看门狗约束；玩家模块加载、入口、动作方法与最终序列化计入玩家 CPU。公开 JSON 快照冻结只读取捕获的 JSON.parse 产生的自有数据属性；稠密数字网格不逐格构造属性描述符，避免额外的包装成本。

## 观察和事件

PaperObservation 使用独立 schema，不再继承整个 PaperState。公开 JSON 观察包含 tick、maxTicks、身份、board、双方位置/出生点和 events；内部 PRNG 状态、alive 和可空头部位置不进入当前玩家视图。内部世界与规范动作格式不变，已有规则和回放推进逻辑继续复用。

GameRules.observe 的可选 context.events 提供上一 tick 的冻结事件；首 tick 为空。游戏负责按可见性筛选，圈地的事件均公开。引擎实时运行和回放核验都逐 tick 传入重建事件，播放器在检查点跳转后也重建输入 tick 前一轮的事件，不把当前 tick 的结算结果提前提供给玩家。

官方 bot 改为读取公开 reset 事件清除失效计划，不再记录预期落点猜测重置。寻路和风险计算在玩家自身代码中计费，没有提高官方 bot 的限额或添加特殊执行路径。

## 发行兼容

当前发行仍是 `paper@0.2.0` / v2。v1 没有用户，不提供 v1 执行或回放兼容。网页、CLI 和独立开发包只注册当前规则，不保留旧观察解析器或历史发行选择分支；发行或协议不匹配的回放会拒绝。未发布的中间 v2 开发代码按当前 SDK 更新。

没有执行 npm 发布、部署、数据库迁移或用户数据改写；未删除本地已有调试产物。发布时生成当前发行的开发包。

本目录先前的性能记录和原始数据描述接口重构前的内部阶段，不代表当前 API 的性能结果。旧基准脚本依赖当时的玩家入口和 SDK 契约，不能直接套用当前工作区重现旧测量。

## 验证结果

最终 `paper@0.2.0` / v2 工作区通过 `pnpm check`：类型、lint、格式与测试均完成，397 项测试通过，35 项依环境条件跳过，保留 3 条既有 web 副作用导入 lint 警告。覆盖多角色自定义命令集合、覆盖规则、原子回滚、旧 tick 提交通道拒绝、捕获错误后的失败锁定、非 undefined 返回值拒绝、工厂系统失败、跨 tick 原型污染、只读嵌套数据、公开观察校验、实时/重演/跨检查点事件一致性与不匹配发行的拒绝。

`pnpm test:artifacts` 通过，包括全量生产构建、6 个打包包、12 个公开 exports、仓库外严格 NodeNext 类型、真实隔离子进程和完整比赛、编译后 API，以及 1 个独立 ZIP 开发包的实际下载、安装、官方对手、批量比赛、调试、日志和回放流程。更新后的沙箱原生基准可正常执行，相关文档的 30 个本地链接有效。

另以 seed 42、43 运行两场当前正式默认限额下的官方 bot 对战，均完整 600 tick、零执行错误，回放重演摘要一致。摘要分别为 `37da4283575a23d083e75b7f48c473ed7bccc58b40e8a192a1184ec1efc70b78` 与 `f1926325944a8422817e8efd736adf3f10009e75a8640b8ec6183ab5b33644c3`。没有据此计算跨轮性能提升；低配硬件、真实 PostgreSQL 和 Linux cgroup 的验证范围仍受本机环境限制。
